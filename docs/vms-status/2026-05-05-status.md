### Тонкие места cgo в `internal/analytics/lpr/engine.go`

- **Memory ownership**: каждый `platecore_get_result_by_index` обязан
  иметь парный `platecore_processing_release`; каждый `platecore_to_jpeg`
  парный `platecore_jpeg_release`. Сейчас сделано вручную. **Нет
  unit-теста на счётчик allocations** — длинный run даст leak только
  через `top` / `pmap`. Под нагрузкой PlateCore ещё не валидировано.
- **C++ header** не инклюдится из cgo (default args в struct fields).
  Типы и прототипы переобъявлены вручную в cgo-блоке engine.go (строки
  17-89). Если в новой версии PlateCore SDK поменяют layout структур —
  получим silent corruption. Защиты от этого нет, нужен smoke-тест на
  каждый bump SDK.
- **Bool/int mismatch** между control-plane и `lpr.Config` (Stream / Crop /
  Draw — `int` в Go, но control-plane шлёт `bool`). Сейчас это known issue:
  `json.Unmarshal` валится с `cannot unmarshal bool into ... int`,
  Configure возвращает error → reader не стартует. Лечится либо в
  control-plane (int 0/1), либо здесь (bool + конвертер). Решение пока
  не выбрано.

### Hard-coded пути / магические числа

- `cgo LDFLAGS: ... -Wl,-rpath,/opt/platecore/lib` в `lpr/engine.go:9`.
  Меняется только пересборкой image. Норма для нашего runtime, но если
  переедем на nix/системный install — придётся править.
- `internal/analytics/reader.go`: `jobs := make(chan *frameJob, 10)` —
  захардкожен 10. Если ввести очень бурный keyframe-flow с FPS=60,

- `internal/analytics/publisher.go`: `thumbnailUploadTimeout = 3 * time.Second`.
- `internal/analytics/decoder.go`: `h264NALUTypeIDR = 5` etc. — magic
  numbers H.264 spec, OK.

### Почему go-astiav v0.16.0, а не latest (v0.40+)

go-astiav жёстко привязан к мажорной версии FFmpeg:
- `v0.40.0` → требует ffmpeg n8.0
- `v0.30.x` → ffmpeg n7
- `v0.20.x` → ffmpeg n6
- **`v0.16.0` → ffmpeg n5.1.2** ← matches debian:bookworm
- `v0.13-0.15` → ffmpeg 5.0/5.1

Bookworm ships ffmpeg 5.1, поэтому пинимся к v0.16.0. API подмножество,
которое использует наш `decoder.go` (FindDecoder / SendPacket /
ReceiveFrame / ScaleFrame / FrameData.Bytes), идентично в v0.16 и v0.40 —
переехать когда сменим base image на trixie/ubuntu 24+ (ffmpeg 6/7/8) —
тривиально.

## 9. Что делать с форком дальше

### Краткосрочно (Phase 4.x → 5)

- **bool/int unmarshal в lpr.Config**: либо контроллер шлёт int, либо тут
  меняем на bool + конвертер. Решение нужно для thumbnails в MinIO →
  без них control-plane не положит JPEG в БД.
- **runOnReady wget hook**: image не содержит wget, hook падает с
  `executable file not found`. Либо `apt install wget` в runtime stage,
  либо скрипт hook через нативный Go (proxy внутри control-plane).
- **bgrFrames канал** (брифом упоминался размером 4) сейчас не
  существует — fanout синхронный. OK для одного модуля, но при добавлении
  motion / person как параллельных модулей понадобится буфер копий BGR
  либо pool. Сейчас рассчитано на синхронный path.

### Stub-модули (motion, person)

Не реализованы. Брифом задумано как plug-in pattern: модуль регистрируется
через `analytics.RegisterModule`, в Configure инициализирует свои
конфиги, в Process получает Frame. Реальные кандидаты:
- **motion** — тривиальный, MOG2 или frame-diff на BGR. Без cgo, чистый
  Go или OpenCV-bindings. Хорошо ложится в текущую архитектуру.
- **person** — YOLO/MobileNet-SSD через ONNX runtime (cgo). Нужно
  отдельная зависимость + ONNX models vendor. Сложнее. Не приоритет,
  если в LPR-кейсе уже всё что надо.

### Phase 7 hardening идеи

- **CUDA в analytics image**: base `nvidia/cuda:12.x-runtime-ubuntu22.04`,
  `--gpus all` в compose, копировать `libcublasLt.so.12`. Скачет размер
  image до ~7 GB но даст 3-5x throughput PlateCore.
- **Watchdog для license-proxy в entrypoint.sh**: сейчас если proxy
  падает, мы только логируем и продолжаем с mediamtx; LPR деградирует
  тихо. Добавить периодический probe + автоматический рестарт proxy
  через `kill 0` loop.
- **Sandbox для cgo / seccomp profile**: PlateCore — закрытый бинарь,
  доверять ему полностью не должны. seccomp-профиль для контейнера
  ограничит сурфейс. Не блокер, но nice-to-have.
- **Prometheus metrics экспорт из analytics**: счётчики frames-decoded,
  module-process-duration, publisher-errors, MinIO-upload-latency.
  Сейчас visibility только через grep по логам. Mediamtx уже имеет
  `/metrics` endpoint — проверить можно ли туда экспортнуть.
- **Stream `lpr_events` создаётся control-plane'ом** в Task 4.2 — пока в
  тесте создавал руками через nats CLI. До интеграции — без этого
  publish фейлится.
- **Audio trim** в playback (см. §6 PR #3) — улучшит UX seeking.
